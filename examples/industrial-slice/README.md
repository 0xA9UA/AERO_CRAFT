# Industrial reference slice

This is original AERO_CRAFT example code: a coal generator, cables and an electric
furnace. It is a small working reference for port architecture, not a Tech Reborn
port or a claim of feature parity. Create a new instance with AERO_CRAFT's
`create_industrial_example` tool; never overwrite an existing port with it.

Build the generated project with `python3 /path/to/AERO_CRAFT/aero.py build .`.
The build installs pinned API declarations, typechecks actual runtime JavaScript,
runs seven simulation and seven real-adapter regression tests, and creates
`dist/__MOD_ID__-0.1.0.mcaddon`.

Import the addon and enable its behavior and resource packs. In Creative, find
Coal Generator, Energy Cable and Electric Furnace under Construction. Place a
generator, a cable and a furnace in a straight line with touching faces. Hold
coal and interact with the generator, then choose **Insert held coal**. Hold raw
iron and use the corresponding furnace button. Reopen the furnace and choose
**Collect iron ingots**. The colored panel textures distinguish all three blocks.

Recipes also exist for survival crafting. One coal supplies 160 energy; smelting
one raw iron costs 20 energy. Each machine stores up to 64 energy. The example
advances every five game ticks. It preserves fuel, input, output and progress in
a versioned world dynamic property. Loaded face-adjacent networks conduct power;
unloaded chunks pause. Break a machine to recover unused fuel, input and finished
output. Stored energy and the already burning coal are not recoverable.

Machines and cables are explicitly immovable by pistons. This is a deliberate
adaptation: state belongs to a dimension and block position, so moving a block
without migrating its state would lose or duplicate its contents. The native
scenario powers a piston beside a loaded machine and a stone control, confirms
only the stone moves, and checks the machine's input is preserved. The same
scenario destroys and explodes machines to verify inventory drops through the
actual `onBreak` callback. Administrative replacement without `destroy` bypasses
that callback; empty machines before replacing their blocks with editing tools.
Pending forms also recheck the original machine instance, player connection,
dimension and reach before changing inventories. A broken and replaced machine
cannot be accessed through the old machine's still-open form.

The reference intentionally supports at most 64 tracked blocks, one furnace
recipe, a single transfer tier, and a simple first-machine-first distribution
policy. Larger ports need scalable network indexing, explicit migrations,
recipe matching, additional tiers, multiplayer tests and source-backed parity
acceptance criteria. These choices are visible implementation limits.

`tests/native-smoke.js` exercises real placed blocks, transfer, processing,
disconnection, inventory quantities and restart persistence using the same engine
adapter as the UI. Run AERO_CRAFT native validation against the registered Bedrock
server. Native validation does not observe a connected client's rendering or
touch interactions: verify these separately before a client-ready claim.

All example textures are original procedural 16px images generated by
`aerocraft.industrial`; no source-mod assets are redistributed.

The reference follows the official [startup event registry](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/startupevent),
[custom-component registration](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/blockcomponentregistry),
[block ticking requirements](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/blockcomponents/minecraftblock_tick)
and [material instances](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/blockcomponents/minecraftblock_material_instances).
The [movable component](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/blockcomponents/minecraftblock_movable)
sets `movement_type` to `immovable`; [onBreak semantics](https://learn.microsoft.com/en-us/minecraft/creator/scriptapi/minecraft/server/blockcustomcomponent)
distinguish destruction from plain block replacement.
Recipes include the unlock metadata shown in [Mojang's current samples](https://github.com/Mojang/bedrock-samples/blob/main/behavior_pack/recipes/iron_ingot_from_nuggets.json).
These documented shapes are also exercised by the native scenario; declarations
and successful packaging alone are not sufficient evidence of engine support.
